# 数据模型 — 商户域（merchant / 分组 / 商户-通道 / 商户提现）

> 域文档，从 `运营平台-P1数据模型草案.md` 拆出。P1 第 2 块。
> 范围：merchant / merchant_group / merchant_channel / merchant_withdraw；并约定商户账户余额/流水的接入方式（账户表本身见后续「账户/对账」域文档）。
> 目标：把商户主体、商户-通道费率、商户提现（冻结模型）定清楚；与 RBAC（用户）、通道域、账户域的边界划清。

最后更新：2026-07-15
状态：⬜ 待评审

---

## 1. 设计原则

1. **商户余额不内嵌**：商户可用余额、冻结余额、预付款统一进账户表（`account_balance`，account_type=1商户），merchant 表只存主体属性。**任何余额变更必须经账户流水（`account_ledger`）事务**，禁止直接 update（见账户域）。
2. **费率快照**：下单/提现时的费率从 `merchant_channel.merchant_rate` 取，并快照到订单；此处 merchant_channel 是费率来源。
3. **提现冻结模型**：申请→冻结、通过→出账、拒绝→解冻，全程账户流水（详见 §3.2）。
4. **资金操作审计**：调额、改费率、提现审核 → 账户流水 + sys_operation_log 三件套。
5. **审计字段每表显式**：`created_at / updated_at / created_by / updated_by`；主体表带 `deleted_at`（软删）。
6. **敏感字段加密**：商户密钥、密码哈希禁明文。

## 3. 商户账户接入（引用账户域）

商户余额在统一账户表，本域只约定用法：

- `account_balance`（account_type=1, account_id=merchant.id）：`balance`（可用）、`frozen_balance`（冻结）、`prepaid`（预付款，P1 预留）。
- 每笔变动写一条 `account_ledger`（account_type=1），带 `balance_before/balance_after`、`biz_type`、`order_no`。

### 3.1 商户提现状态机 + 冻结模型

```
申请(待审核)
  │  同事务：balance −= amount，frozen += amount；写 ledger(提现申请)
  ├──审核通过──► 通过 ──出账──► 成功
  │            同事务：frozen −= amount；写 ledger(提现出账) + operation_log
  └──审核拒绝(必填remark)──► 拒绝
               同事务：frozen −= amount，balance += amount；写 ledger(提现解冻) + operation_log
```
- 通过免备注、拒绝必填（PRD §10.2）；审核权限 `withdraw:audit`（见 RBAC 域）。

### 3.2 商户调额（人工）

`account_balance` 变更 + 写 `account_ledger`(biz_type=调额，带 operator_id/ip/remark) + 写 `sys_operation_log`。入口=商户列表余额列「调整」（PRD §3.1/§3.8）。

## 4. 关键流程

### 4.1 创建商户
1. 写 `merchant`（mch_no 生成、默认密码来自系统配置）。
2. 初始化 `account_balance`（account_type=1, balance=0, frozen=0）。
3. **联动建 RBAC 用户**：写 `sys_user`（terminal=2 商户后台、merchant_id=本商户、role_id=「商户」角色、login_account=表单登录账号、login_password_hash=默认密码哈希）。**登录账号唯一性在 sys_user 校验**。
> 「更多」菜单映射：重置登录密码 → `sys_user.login_password_hash`；重置提现密码 → `merchant.withdraw_password_hash`；重置商户密钥 / 查看商户密钥 → `merchant.mch_key`。

### 4.2 开通通道（通道配置抽屉）
- 写/更新 `merchant_channel`（merchant_id, channel_id, merchant_rate, rebate_rate, status）。
- 一键改费率（全部/选择/分组）：按范围批量 update `merchant_channel.merchant_rate`；若「通知到群」开 → 触发机器人通知；落 operation_log。

### 4.3 商户提现审核
- 见 §3.1 状态机；顶栏「商户提现 N」= `merchant_withdraw.status=待审核` 计数。
