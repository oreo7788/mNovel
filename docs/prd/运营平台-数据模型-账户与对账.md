# 数据模型 — 账户与对账域（account_balance / account_ledger / 对账）

> 域文档，从 `运营平台-P1数据模型草案.md` 拆出。P1 第 4 块，**对账地基**。
> 范围：account_balance（当前态）/ account_ledger（流水，事实源）/ account_reconcile_log（对账记录）。
> 目标：把"流水是唯一事实源、新旧余额成对、链式连续、幂等、可对账"这五件事定死。商户/通道/代理/系统/供应商/商户预付 六类账户共用这套结构（对应 PRD 账户记录 6 Tab）。

最后更新：2026-07-15
状态：⬜ 待评审

---

## 1. 设计原则

1. **流水是唯一事实源**：每笔资金变动 = 一条 `account_ledger`，**必须成对写 `balance_before / balance_after`**。`account_balance` 是当前态缓存，可由流水重算，二者必须一致。
2. **双写同事务**：余额变更与流水写入在**同一数据库事务**；对 `account_balance` 行加 `SELECT … FOR UPDATE`（或乐观 `version`）防丢失更新。**禁止绕过流水直接改余额**。
3. **链式连续**：每个账户的流水按 `seq` 单调递增；`第 N 行.balance_before = 第 N−1 行.balance_after`。对账任务据此校验断链。
4. **硬约束**：`balance_after = balance_before + (direction × amount)`；应用层写前校验 + 对账任务复算，不一致即告警。
5. **幂等**：`(order_no, biz_type, account_type, account_id)` 唯一约束，防止支付回调/补单重复入账（双写）。
6. **只追加**：流水表禁物理删除、禁改历史行；冲正用反向流水（`biz_type=补偿/退款`），不改原行。
7. **审计**：流水带 `operator_id / operator_ip / remark / source`，人工调额必填。

## 4. 写入序列（核心场景）

> 金额算法依赖计费规则表 A/B 节；此处只定**结构**。每条都在同一事务内：取 `seq = 上条+1`、算 before/after、写 ledger、update balance。

### 4.1 支付成功（订单 amount=M，商户服务费=mf，通道成本=cc，均来自订单快照）

```
商户账户(1)  支付入账      +M        before → before+M
商户账户(1)  商户服务费    −mf       → 净增 M−mf
系统账户(4)  商户服务费    +mf       平台收服务费
通道账户(2)  通道成本      …(待计费表：通道余额增减方向) 
```
> 通道/系统侧的通道成本入账方式（支付时还是结算时、方向）待计费表 B3/C 节定。

### 4.2 商户提现（amount=A，service_fee=sf）

```
申请：  商户账户(1)  提现申请   −A       balance−=A
                       (同时 frozen += A，写 balance_before/after 用 balance)
通过：  商户账户(1)  提现出账   无余额变动(frozen−=A)，或记一条 0 元流水标记
拒绝：  商户账户(1)  提现解冻   +A       balance+=A (frozen−=A)
```
> 冻结金额是否单独入流水：建议 frozen 变动**不产生 balance 流水**（只在 balance 上记申请/解冻两条），frozen 由提现单状态推导；若要 frozen 可审计，另记只读冻结流水（开放点 B）。

### 4.3 调额（人工）

```
对应账户  调额  ±X   source=手动调额, operator_id/ip/remark 必填
```
+ 同步写 `sys_operation_log`（RBAC 域）。

### 4.4 结算（余额清零 / 结算昨日）

```
商户账户(1)  结算入账   按结算方式结转累计/昨日跑量到结算池（科目待计费表 C4）
```

## 5. 对账机制

1. **链式校验**：对每个账户，按 `seq` 扫描，校验 `本行.balance_before == 上行.balance_after`；断链记 `chain_ok=0`。
2. **余额复算**：`expected = 期初 + Σ(direction×amount)`；与 `account_balance.balance` 比，差值记 `diff`。
3. **执行**：定时任务（建议每日 UTC+8 00:00 后 + 可手动触发），按账户生成 `account_reconcile_log`。
4. **告警**：`status=0` 或 `diff≠0` → 告警（机器人/群通知），人工介入；**不自动改账**，冲正走反向流水。
5. **幂等回放**：对账只读，可重复执行；幂等键 `(account_type, account_id, period_date)`。
