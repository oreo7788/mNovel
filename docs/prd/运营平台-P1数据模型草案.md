## 0. 设计原则（先对齐这 5 条，再看表）

1. **账户流水是账务唯一事实源**：每一笔资金变动 = 一条 `account_ledger` 记录，**必须成对写** `balance_before` **/** `balance_after`，与余额更新在**同一数据库事务**内完成。`account_balance` 是当前态缓存，可由流水重算，二者必须一致（对账校验）。
2. **费率/余额快照**：下单时把当时的「商户费率、通道费率、代理费率」**快照落到订单**；后续改费率不影响历史订单与已生成的流水。
3. **金额** `decimal(18,4)`；**费率** `decimal(10,6)`（小数 ‰ 语义，如 0.003）；**金额一律非负存绝对值**，方向用 `amount` 的正负或 `direction` 字段表达。
4. **软删除**：业务主体表带 `deleted_at`；资金/订单/流水表**禁止物理删除**（只追加，不修改历史行）。
5. **审计字段**：所有主表统一带 `created_at / updated_at / created_by / updated_by`（下文不再重复列出）。

## 1. 实体关系总览

```
channel_type 1───* channel 1───* channel_rate        (三档费率，按金额区间)
                          ├───* channel_pay_rule     (收款方式与规则)
                          └──1 channel_dev_config    (开发配置)

merchant *───* channel        (merchant_channel：商户费率/返佣费率/开通状态)
   │
   └──* order ──* account_ledger   (订单产生流水)
                         ↑
merchant_withdraw ────────┘        (提现产生流水：申请冻结/通过出账/拒绝解冻)

account_balance  ←——  account_ledger   (当前态 vs 流水，事务双写、定期对账)

sys_user ─── sys_role                (P1 基础 RBAC)
system_config (KV，按区块)           (区块级保存)
operation_log                        (资金类操作落日志)
```

## 3. 关键状态机与写入序列



### 3.1 订单状态机（status）

```
待支付 ──支付成功──► 支付成功（account_status=已入账，写商户入账+服务费流水）
   │                                   │
   │──支付失败──► 支付失败              │──(异常)──► 异常
   └──超时/未出码──► 未出码             │
                                        └── 回调通知（callback_status 独立流转）
```

- **支付成功时同事务**：`order.status=支付成功` + `account_status=已入账` + 写 ledger（商户应收入账、商户服务费、通道成本按计费规则 B/A 节）。
- 入账金额、服务费、通道成本**均用订单快照值**计算，保证历史可复算。



### 3.2 商户提现状态机（status）+ 冻结模型

```
申请(待审核)
  │  同事务：account_balance.balance −= amount，frozen += amount；写 ledger(提现申请)
  ├──审核通过──► 通过 ──出账──► 成功
  │            同事务：frozen −= amount；写 ledger(提现出账)
  └──审核拒绝(必填remark)──► 拒绝
               同事务：frozen −= amount，balance += amount；写 ledger(提现解冻)
```

- 冻结模型保证「待审核金额不重复可提」，拒绝可逆，全程有流水。
- 通过免备注、拒绝必填（PRD §10.2）。



### 3.3 调额（人工）

`account_balance` 变更 + 写 ledger(biz_type=调额，带 operator_id/ip/remark) + 写 operation_log。资金类操作三件套缺一不可。

## 4. 待技术评审的开放点

1. **账户余额表结构**：用统一 `account_balance`（推荐，对账友好）还是在各主体表内嵌 `balance` 列？→ 建议统一表。
2. **金额精度**：`decimal(18,4)` 是否够？费率 `decimal(10,6)` 是否够？（分润可能需更高精度）
3. **流水 biz_type 枚举**：与计费规则表 F2 节联动定稿。
4. **订单/流水并发**：支付成功回调与轮询补单可能并发同写，需 `order_no` 唯一约束 + 状态机乐观锁（`where status=待支付`）。
5. **对账任务**：是否需要一个 `account_reconcile` 定时任务（流水重算余额 vs balance 不一致告警）？建议 P1 就建。
6. **分库分表预留**：订单/流水是高增长表，是否一开始就按 merchant_id 或时间分表？（影响 P1 表结构）
7. **时区**：所有时间字段统一存 UTC，展示层按 UTC+8（日切 00:00 UTC+8）。
