# 运营平台 — MVP 与迭代计划

> 基于 `运营平台-PRD-v0.6.md`。目标：用最小可闭环范围先立住平台，其余边做边完善。
> 原则：**纵向打通 > 横向铺全**。每个 Phase 都要能独立交付一个"用户能跑通"的能力，而不是半成品堆叠。

最后更新：2026-07-15

---

## 总览

| Phase | 主题 | 一句话目标 | 前置依赖 |
|-------|------|-----------|---------|
| **P1** | 核心交易闭环 | 配通道 → 商户下单 → 订单可见 → 商户提现 → 基础对账 | 计费规则表 A/B；数据模型；技术选型 |
| **P2** | 主体扩展 + 资金完善 | 代理、供应商、多通道提现、异常处理、调额/结算 | P1 上线；计费规则表 C/D/E |
| **P3** | 统计与运营增强 | 全量日终/账户记录、机器人、权限精细化、导出 | P2 数据沉淀 |
| **P4** | 补全（边做边完善） | 订单详情/补单/回调、提现审核细节、监控区、枚举锁定 | 有真实数据后 |

## Phase 1 — 核心交易闭环（MVP）

**目标**：跑通"支付聚合运营"的最小主流程，平台可用、账可对。

### 包含模块

| 模块 | P1 范围（做到哪） | 暂不做 |
|------|-----------------|--------|
| 登录 | 用户名/密码/图形码/记住密码；基础 RBAC（超管/运营） | 谷歌验证（关系待定） |
| 首页 | 看板 9 指标（今日/昨日）；系统开关；提现待办计数 | 底部三 Tab 速览、监控区 |
| 通道类型 | 全量 CRUD + 删除二次确认 | — |
| 通道 | 列表、创建/编辑（基本信息 + 三档费率 + 收款方式规则）、开发配置、启停 | 绑定、通道测试、5 个设置弹窗、工作指标列 |
| 商户 | 列表、新建/编辑、通道配置、状态管理 | 通道绑定、调额、分组、一键改费率、更多菜单 9 项、群发艾特 |
| 订单 | 下单接入、订单列表（14 筛选 + 枚举 + 当前条件成功率）、导出 | 详情、补单、回调弹窗 |
| 商户提现 | 列表 + 审核（通过免备注/拒绝必填）+ 状态机 | — |
| 账户记录 | **商户账户** 1 个 Tab（流水成对新旧余额） | 其余 5 Tab |
| 日终 | — | 全部转 P3 |
| 系统配置 | 应用配置（网址/超时/保留天数/系统开启）；安全配置基础项 | 机器人、平台配置播报群组 |
| 操作日志 | 资金类操作（提现/改费率/调额）落日志 | 登录日志、操作日志列表页 |

### P1 验收（能跑通的标志）
- [ ] 可创建通道类型 → 配置通道（含费率与收款规则）→ 创建商户并开通通道
- [ ] 商户发起支付 → 订单列表可见，状态/筛选/成功率正确
- [ ] 商户申请提现 → 运营审核通过/拒绝（拒绝强制备注）→ 余额与流水正确变动
- [ ] 商户账户流水每笔带新旧余额，可按时间导出对账
- [ ] 关闭系统开关 → 拒收新单
- [ ] 资金操作全部有操作日志

### P1 前置（开工前必须就绪）
1. **计费规则表 A/B 节定稿**（利润公式、入账规则）——否则账户流水和提现无法验收
2. **数据模型设计**：商户/通道/订单/账户流水 的表结构与科目关系
3. **技术选型**：前端框架 + 后端 + 部署（已排除沿用 `web/`）

## Phase 2 — 主体扩展 + 资金完善

**目标**：补齐多主体（代理/供应商）与资金动作，形成完整运营能力。

### 包含模块
- **代理管理**：列表/创建/编辑/行内改状态/操作菜单/详情（依赖代理对称性结论）
- **供应商管理**：列表/创建/编辑/通道绑定/结算设置/预付预警/一键结算（**无导出**）
- **通道提现 + 代理提现**：列表 + 审核（同商户提现规则）
- **异常订单**：列表 + 判定规则 + 操作（依赖异常判定结论）
- **商户资金动作**：调额、一键改费率（全部/选择/分组）、结算配置、分组管理
- **商户更多操作**：详情、查看密钥、重置 4 类密码/密钥、测试
- **通道增强**：绑定、5 个行内设置弹窗（费率/代理费率/权重/提现服务费/信用额度）、通道测试
- **首页底部速览**：商户/通道/代理三 Tab

### P2 验收
- [ ] 代理、供应商可独立配置并参与分润/结算
- [ ] 三类提现审核统一规则，顶栏待办计数准确
- [ ] 异常订单可识别与处理
- [ ] 所有资金/费率操作可审计（操作日志）

### P2 前置
- 计费规则表 C/D/E 节定稿（结算/提现/科目）
- 代理是否对称商户的结论
- 异常订单判定规则

## Phase 3 — 统计与运营增强

**目标**：数据可见、可导出、可对账；运营自动化（机器人）。

### 包含模块
- **账户记录全 6 Tab**（商户/通道/代理/系统/供应商账户 + 商户预付），全可导出
- **日终统计全 8 Tab**（仅商户日终可导出，其余只读），按 UTC+8 日切
- **机器人配置**：频道、开关项、欧易 USDT 来源、UJ 指令、权限账号表、群通知
- **角色权限精细化**：权限分配弹窗（菜单/操作树）、提现审核权限分配
- **登录日志 / 操作日志**：完整列表 + 筛选 + 枚举
- **术语统一**：代理名称/代理商名称/代理；供应商结算方式用词

### P3 前置
- P2 数据沉淀（日终/流水需真实跑量数据）
- 账户流水「类型」枚举定稿

---

## Phase 4 — 补全（边做边完善）

**目标**：用真实运行数据补齐交互细节与枚举。按需排期，不阻塞主线。

- 订单详情、补单、回调确认/结果
- 提现审核弹窗 UI 细节、状态机色标
- 数据统计「类型/是否盈利/来源」枚举与示例值（需有数据行截图）
- 通道列表「工作指标」列含义确认
- 首页监控区（目前**暂不考虑**，确认是否做）
- 安全配置「登录谷歌验证」与登录页关系确认

## 关键路径与风险

| 风险 | 影响 | 缓解 |
|------|------|------|
| 计费公式不定 | **阻塞 P1 验收** | 《计费与对账规则确认表》优先对齐 A/B，本周内定稿 |
| 数据模型返工 | 阻塞 P1 开发 | 开工前评审表结构，尤其账户流水科目 |
| 利润无法即时验收 | 日终利润列空跑 | P1 先用"商户服务费−通道成本"近似，代理费 P2 补 |
| 截图细节边做边补 | 可能返工 | 接受；以真实数据为准，不纠结截图 |
