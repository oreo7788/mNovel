# 数据模型 — 通道域（channel_type / channel / 费率 / 收款规则 / 开发配置）

> 域文档，从 `运营平台-P1数据模型草案.md` 拆出。P1 第 3 块。
> 范围：channel_type / channel / channel_rate（三档费率）/ channel_pay_rule（收款方式规则）/ channel_dev_config（开发配置）。
> 目标：定清通道主体、三档区间费率、收款规则（区间/固定值）、加密的开发配置；与商户域（merchant_channel 费率来源）、账户域（通道余额）、订单域（路由命中费率档）划清边界。

最后更新：2026-07-15
状态：⬜ 待评审

---

## 1. 设计原则

1. **通道无业务编码**：按评审决议，`channel` 表**去掉 `code`**，用内部 `id` + `name` 标识；上游对接所需的应用ID/密钥放 `channel_dev_config`。`channel_type` 仍保留 `code`（类型编码）。
2. **通道余额走账户表**：`channel.balance` 不内嵌，统一进 `account_balance`（account_type=2通道）；变更必经账户流水。本表只存主体属性。
3. **三档费率按金额区间**：`channel_rate` 以 `(min_amount, max_amount)` 表达档位，下单按金额命中档；区间必须**不重叠、全覆盖**。
4. **费率快照**：下单时把命中的 `channel_rate.rate` 快照到订单（`channel_rate_snapshot`）+ 算定 `channel_cost`，改费率不影响历史单。
5. **开发配置加密**：`channel_dev_config` 的 secret/密钥**加密存储**，受系统配置「开启通道开发配置」开关控制可见性。
6. **审计字段每表显式**：`created_at / updated_at / created_by / updated_by`；主体表带 `deleted_at`。
7. **派生列不落库**：成功率(昨/今)、工作指标由订单实时聚合（或缓存表，P3）。

## 2. 表清单

### 2.1 channel_type 通道类型

| 字段 | 类型 | 说明 |
|------|------|------|
| id | bigint PK | |
| code | varchar(64) | 类型编码，**unique** |
| name | varchar(128) | 类型名称 |
| status | tinyint | 1正常 / 0停用 |
| sort_order | int | 排序号 |
| remark | varchar(255) | 备注 |
| created_at / updated_at / deleted_at | datetime | |
| created_by / updated_by | bigint | 用户ID |

> 删除走二次确认 + 关联商户解锁（FR-CT1），实际为"停用/解锁"，不物理删。

### 2.2 channel 通道

| 字段 | 类型 | 说明 |
|------|------|------|
| id | bigint PK | （无业务编码 code） |
| name | varchar(128) | 通道名称 |
| type_id | bigint FK→channel_type | 通道类型 |
| status | tinyint | 1启用 / 0停用 |
| poll_weight | int | 轮询权重（订单路由加权随机） |
| withdraw_fee | decimal(18,4) | 提现服务费 |
| credit_limit | decimal(18,4) | 信用额度 |
| credit_enabled | tinyint | 信用额度开关 |
| remark | varchar(255) | |
| created_at / updated_at / deleted_at | datetime | |
| created_by / updated_by | bigint | |

> 通道余额在 `account_balance`（account_type=2）；本表不存 balance。
> 派生列（成功率昨/今、工作指标）不落库。

### 2.3 channel_rate 通道费率（三档，按金额区间）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | bigint PK | |
| channel_id | bigint FK→channel | |
| min_amount | decimal(18,4) | 区间下限（含） |
| max_amount | decimal(18,4) | 区间上限（不含；0=无上限） |
| rate | decimal(10,6) | 该档费率（小数，0.003=3‰） |
| created_at / updated_at | datetime | |
| created_by / updated_by | bigint | |

> 索引：`(channel_id, min_amount)`。
> 约束：同一 channel 的区间**不重叠、全覆盖**（应用层校验 + 唯一性近似约束）。下单时 `min_amount <= amount < max_amount` 命中档位。

### 2.4 channel_pay_rule 收款方式与规则

| 字段 | 类型 | 说明 |
|------|------|------|
| id | bigint PK | |
| channel_id | bigint FK→channel | |
| pay_method | varchar(64) | 收款方式（支付宝H5 / 微信私服 / 银行卡…） |
| rule_type | tinyint | 1=区间 / 2=固定值 |
| min_amount | decimal(18,4) | rule_type=1 下限（含） |
| max_amount | decimal(18,4) | rule_type=1 上限（不含；0=无上限） |
| fixed_values | varchar(512) | rule_type=2 用，`|` 分隔，如 `98|199|299` |
| status | tinyint | 1启用 / 0停用 |
| created_at / updated_at | datetime | |
| created_by / updated_by | bigint | |

> 索引：`(channel_id, pay_method)`。一个通道可配多种收款方式，每种一条规则。

### 2.5 channel_dev_config 开发配置（敏感，1:1）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | bigint PK | |
| channel_id | bigint FK→channel | **unique**（1:1） |
| app_id | varchar(128) | 上游应用ID/商户号 |
| secret | varchar(255) | **加密存储** |
| public_key | text | 上游公钥，**加密** |
| private_key | text | 我方私钥，**加密** |
| callback_url | varchar(255) | 回调地址 |
| sign_type | varchar(32) | 签名方式（MD5/RSA…） |
| extra | json | 扩展参数（上游差异化字段） |
| created_at / updated_at | datetime | |
| created_by / updated_by | bigint | |

> 受系统配置「开启通道开发配置」开关控制可见性。查看/编辑需权限。

## 3. 关键流程

### 3.1 创建/编辑通道
1. 写 `channel`（基本信息 + poll_weight + credit_limit）。
2. 写 `channel_rate`（三档区间费率，校验不重叠全覆盖）。
3. 写 `channel_pay_rule`（各收款方式规则）。
4. 写 `channel_dev_config`（加密存上游凭据）。
5. 初始化 `account_balance`（account_type=2, balance=0）。

### 3.2 订单路由命中费率档（下单时）
1. 按收款方式 + 金额筛可用 `channel_pay_rule`（rule_type=1 命中区间，或 rule_type=2 命中固定值）。
2. 在候选通道中按 `poll_weight` **加权随机**选一个（status=启用）。
3. 按金额命中该通道 `channel_rate` 档 → 取 `rate`。
4. **快照到订单**：`channel_rate_snapshot = rate`，`channel_cost = amount × rate`（计费规则 A2 节）。
5. 信用额度检查：若 `credit_enabled` 且订单会超出 `credit_limit − 已用`，则跳过该通道（规则待计费表 E3 定）。

### 3.3 通道余额与提现（P1 结构，功能可后置）
- 通道余额在 `account_balance`(account_type=2)；通道提现复用商户提现冻结模型（待提现域统一），落账户流水。

### 3.4 行内设置与操作（多为 P2，结构预留）
| 操作 | 落点 |
|------|------|
| 通道费率设置 | update `channel_rate` + operation_log |
| 代理费率设置 | 见代理域（按代理配代理费率） |
| 轮询权重设置 | update `channel.poll_weight` |
| 提现服务费设置 | update `channel.withdraw_fee` |
| 信用额度设置 | update `channel.credit_limit / credit_enabled` |
| 绑定 | 商户侧=merchant_channel（商户域）；代理/供应商侧绑定 P2/P3 |
| 复制 | 复制 channel + rate + pay_rule + dev_config（dev_config 凭据是否复制待定） |
| 删除 | 软删 channel；校验无在途订单/绑定 |
| 测试 | 用 dev_config 发起测试支付（P2） |

## 4. 待评审开放点

- **A** 通道无 code 后，**上游对接**若要求一个稳定的业务编码（除 app_id 外），是否需要补回一个 `external_code`？（当前用 dev_config.app_id 承载）
- **B** `channel_dev_config` 1:1 是否够？若同一通道不同收款方式需不同上游凭据，是否加 `pay_method` 维度变 1:N？
- **C** 三档费率区间"不重叠全覆盖"的校验：DB 约束还是纯应用层？（建议应用层 + 落库前校验）
- **D** 信用额度消费规则（E3）：超出是跳过通道、还是允许并告警、还是拒单？（待计费表定）
- **E** 轮询权重为 0 的通道是否完全不参与路由？（建议 0=不参与）
- **F** 复制通道时 `dev_config` 的密钥是否一并复制？（建议不复制，强制重填）
